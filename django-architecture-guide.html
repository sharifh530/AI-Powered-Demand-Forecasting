Django Project Architecture Guide

A beginner-friendly explanation of how the AI-Powered Demand Forecasting platform is structured and how all components connect.

📘 What is Django?

Django is a Python web framework that follows the MVT (Model-View-Template) pattern. It handles routing HTTP requests, database interactions, authentication, and API responses. Think of it as the "backend brain" that serves data to the React frontend.

Project Structure

Django projects are organized into apps — self-contained modules that handle specific domains. This project has 5 apps plus a core configuration directory:

backend/
├── demand_forecast_core/    # Project settings & main URL router
│   ├── settings.py             # Configuration (database, apps, middleware)
│   ├── urls.py                 # Main URL routing entry point
│   └── wsgi.py                   # Production server gateway
│
├── accounts/                     # User authentication & RBAC
├── forecasting/                  # ML models, training, forecasts
├── inventory/                    # Stock tracking & alerts
├── ingestion/                    # Data loading & sample data
├── analytics/                    # Feature engineering & aggregations
│
├── manage.py                    # Django CLI (run commands, migrations)
├── requirements.txt             # Python dependencies
└── db.sqlite3                   # SQLite database (dev environment)

Each App Contains:

models.py

Defines database tables as Python classes. Each class becomes a table; each attribute becomes a column.

views.py

Handles HTTP requests and returns responses (JSON for APIs). Contains the business logic.

serializers.py

Converts database models ↔ JSON. Validates incoming data and formats outgoing responses.

admin.py

Registers models with Django's admin panel (a built-in UI at /admin).

migrations/

Version-controlled database schema changes. Auto-generated when you modify models.

management/commands/

Custom CLI commands (e.g., python manage.py train_models).

Core Configuration

This file configures everything about your Django project:

# Django's built-in apps (admin, auth, sessions) 'django.contrib.admin', 'django.contrib.auth', # Third-party libraries 'rest_framework', # Django REST Framework (builds APIs) 'rest_framework_simplejwt', # JWT token authentication 'corsheaders', # Cross-Origin Resource Sharing # Your custom apps (the 5 modules) 'accounts', 'forecasting', 'inventory', 'ingestion', 'analytics',

REST_FRAMEWORK = { 'DEFAULT_AUTHENTICATION_CLASSES': [ 'rest_framework_simplejwt.authentication.JWTAuthentication', ], 'DEFAULT_PERMISSION_CLASSES': [ 'rest_framework.permissions.IsAuthenticated', # All endpoints require login ], 'PAGE_SIZE': 50, # Return 50 results per API call }
SIMPLE_JWT — Token lifetimes
SIMPLE_JWT = { 'ACCESS_TOKEN_LIFETIME': timedelta(hours=2), # Short-lived token 'REFRESH_TOKEN_LIFETIME': timedelta(days=7), # Long-lived refresh 'ROTATE_REFRESH_TOKENS': True, # Issue new refresh on use 'BLACKLIST_AFTER_ROTATION': True, # Invalidate old tokens }

The 5 Django Apps

1. accounts — User Management

Purpose: Authentication, authorization, role-based access control.

Key Models:

  • User — Custom user model with roles (admin, planner, viewer)

Key Views:

  • register_user — Create new accounts
  • login_user — Issue JWT access & refresh tokens
  • logout_user — Blacklist tokens
  • refresh_token — Exchange refresh token for new access token

2. forecasting — ML Core

Purpose: Model training, inference, forecast storage.

Key Models:

  • ProductCategory — Product categories (Electronics, Beverages)
  • Product — SKU master data
  • Location — Warehouses, stores, distribution centers
  • ModelTrainingRun — Tracks each model tournament run
  • Forecast — Stores predicted demand with confidence intervals
  • ForecastAccuracyRecord — Tracks prediction vs actual

Key Views:

  • ForecastViewSet — List/filter forecasts with summary action
  • ModelTrainingRunViewSet — Leaderboard + trigger_training action

ML Engine:

  • forecasting/ml_engine/models.py — 4 model architectures
  • forecasting/ml_engine/pipeline.py — Training tournament orchestrator
  • forecasting/ml_engine/inference.py — Multi-step forecasting
  • forecasting/ml_engine/metrics.py — WAPE, RMSE, MAE, PICP

3. inventory — Stock Management

Purpose: Track on-hand inventory, calculate days-of-supply, generate reorder alerts.

Key Models:

  • InventorySnapshot — Daily stock levels per SKU-location
  • SafetyStockPolicy — Min/max thresholds
  • InventoryTransaction — Movements (receipts, shipments, adjustments)

Key Views:

  • InventorySnapshotViewSet — Current stock levels
  • low_stock_alerts — Custom action filtering critical stockout risks

4. ingestion — Data Pipeline

Purpose: Load historical sales data, generate sample datasets.

Key Models:

  • SalesTransaction — Historical sales (54,544 rows spanning 2.5 years)
  • IngestionLog — Audit trail of data loads

Management Command:

  • populate_sample_data — Seeds database with synthetic data

Service Module:

  • ingestion/services.py — Deterministic data generator with realistic seasonality

5. analytics — Feature Engineering

Purpose: Transform raw sales into ML-ready features.

Key Models:

  • DemandHistoryAggregated — Daily/weekly rollups
  • TimeSeriesFeatures — 18 features (lags, rolling stats, cyclics)

Features Computed:

  • Lag features: 7d, 14d, 28d, 84d, 364d demand
  • Rolling statistics: 7d/28d mean & std deviation
  • Calendar: day-of-week, month, quarter, is_weekend
  • Cyclics: sin/cos encoding of day-of-week & month
  • Binary flags: promotion_active, holiday_flag

Database Models — The Schema

Django models are Python classes that map to database tables. Each class attribute becomes a column, and Django auto-generates SQL migrations.

Example: Product Model

class Product(models.Model): sku = models.CharField(max_length=50, unique=True) name = models.CharField(max_length=200) category = models.ForeignKey(ProductCategory, on_delete=models.CASCADE) unit_cost = models.DecimalField(max_digits=10, decimal_places=2) unit_price = models.DecimalField(max_digits=10, decimal_places=2) lead_time_days = models.IntegerField() def __str__(self): return f"{self.sku} - {self.name}"

🔗 Relationships Explained

ForeignKey creates a many-to-one relationship. Many products belong to one category.

on_delete=models.CASCADE means: "If the category is deleted, delete all its products too."

Views & APIs — Handling Requests

Django REST Framework provides ViewSets — classes that auto-generate CRUD endpoints.

Example: ForecastViewSet

class ForecastViewSet(viewsets.ModelViewSet): queryset = Forecast.objects.all() serializer_class = ForecastSerializer # This automatically creates: # GET /api/forecasts/ → List all # POST /api/forecasts/ → Create new # GET /api/forecasts/{id}/ → Retrieve one # PUT /api/forecasts/{id}/ → Update # DELETE /api/forecasts/{id}/ → Delete def get_queryset(self): # Filter by query params: ?sku=BEV-001&location=1 qs = super().get_queryset() sku = self.request.query_params.get('sku') if sku: qs = qs.filter(product__sku=sku) return qs

Custom Actions

ViewSets can add custom endpoints beyond CRUD:

@action(detail=False, methods=['get']) def summary(self, request): # Custom endpoint: GET /api/forecasts/summary/ forecasts = self.get_queryset() summary_data = { 'total_forecasts': forecasts.count(), 'avg_demand': forecasts.aggregate(Avg('predicted_demand')) } return Response(summary_data)

URL Routing — Connecting Endpoints

Django uses urls.py to map URL patterns to views. The project has a two-level routing system:

1. Main Router (demand_forecast_core/urls.py)

from django.urls import path, include from rest_framework.routers import DefaultRouter router = DefaultRouter() router.register(r'forecasts', ForecastViewSet, basename='forecast') router.register(r'products', ProductViewSet, basename='product') urlpatterns = [ path('api/auth/login/', login_user, name='login'), path('api/', include(router.urls)), # Include all router URLs ]

2. How URLs Resolve

HTTP Request URL Pattern View Function Action
POST /api/auth/login/ api/auth/login/ login_user Issue JWT tokens
GET /api/forecasts/ api/forecasts/ ForecastViewSet.list Return paginated forecasts
GET /api/forecasts/123/ api/forecasts/{pk}/ ForecastViewSet.retrieve Return one forecast
GET /api/forecasts/summary/ api/forecasts/summary/ ForecastViewSet.summary Custom aggregation

ML Engine — The Forecasting Brain

The ML engine lives in forecasting/ml_engine/ and orchestrates model training & inference independently of Django's web layer.

Architecture

models.py

Implements 4 model classes:

  • WeightedMovingAverageModel
  • HoltWintersModel
  • HistGradientBoostingModel
  • StackedMLPModel

Each has .fit(X, y) and .predict(X) methods.

pipeline.py

Tournament orchestrator:

  • Split data into train/holdout by date
  • Train all 4 models in parallel
  • Evaluate on holdout set
  • Tag champion (lowest WAPE)
  • Save results to ModelTrainingRun

inference.py

Multi-step forecasting:

  • Load champion model from disk
  • Generate 14-day rolling forecasts
  • Compute 90% confidence intervals
  • Save 784 forecasts (8 SKUs × 7 locs × 14 days)

metrics.py

Evaluation functions:

  • wape() — Weighted Absolute % Error
  • rmse() — Root Mean Squared Error
  • mae() — Mean Absolute Error
  • picp() — Prediction Interval Coverage

Complete Request Flow

Here's what happens when the React frontend requests GET /api/forecasts/?sku=BEV-001:

1. Browser sends request with JWT token
↓
2. Django middleware validates JWT
↓
3. URL router matches /api/forecasts/
↓
4. ForecastViewSet.list() called
↓
5. Filters queryset by sku=BEV-001
↓
6. Queries database: SELECT * FROM forecasts WHERE...
↓
7. ForecastSerializer converts models → JSON
↓
8. Response middleware adds CORS headers
↓
9. JSON response sent to browser

Management Commands

Django lets you write custom CLI commands in management/commands/. This project has 3 critical ones:

1. populate_sample_data

python manage.py populate_sample_data

What it does: Seeds the database with 54,544 synthetic sales transactions, 8 products, 7 locations, and computes time-series features.

Location: ingestion/management/commands/populate_sample_data.py

2. train_models

python manage.py train_models --split-date 2026-07-01

What it does: Runs the ML tournament — trains all 4 models, evaluates on holdout, saves results to ModelTrainingRun.

Location: forecasting/management/commands/train_models.py

3. generate_forecasts

python manage.py generate_forecasts --horizon 14

What it does: Loads the champion model, generates 14-day forecasts for all SKU-location pairs, saves to Forecast table.

Location: forecasting/management/commands/generate_forecasts.py

⚠️ Command Execution Order

Always run in this sequence:

  1. python manage.py migrate — Create database tables
  2. python manage.py populate_sample_data — Load data
  3. python manage.py train_models — Train ML models
  4. python manage.py generate_forecasts — Produce forecasts
  5. python manage.py runserver — Start API server

Key Takeaways

Django's Role

Django is the backend server that:

  • Stores data in a database (SQLite/PostgreSQL)
  • Exposes RESTful JSON APIs
  • Handles authentication (JWT tokens)
  • Runs ML training & inference pipelines

React's Role

React is the frontend dashboard that:

  • Sends HTTP requests to Django APIs
  • Displays forecasts in interactive charts
  • Manages user login state (localStorage)
  • Provides CRUD interfaces for SKUs/inventory
