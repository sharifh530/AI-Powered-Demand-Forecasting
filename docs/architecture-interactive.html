End-to-End Forecast Generation Flow

1
Data Ingestion (Daily @ 01:00 UTC)
Sales transactions, inventory snapshots, and product master data pulled from source systems
2
Validation & Staging (01:00 – 01:30)
Schema validation, referential integrity checks, missing value handling, error logging
3
Feature Engineering (02:00 – 03:00)
Compute lag features, rolling statistics, calendar encodings, and promotional signals
4
Model Inference (03:00 – 04:00)
Champion model generates 12-week forecasts with confidence intervals for all active SKU/location pairs
5
Forecast Persistence & API Serving
Forecasts written to PostgreSQL, immediately available via REST API to dashboard and external systems
6
Dashboard Auto-Refresh
React dashboard displays updated forecasts, risk alerts, and accuracy metrics to planners

Core Functional Requirements (Must-Have)

DATA-01
Ingest historical sales transaction data (SKU, quantity, date, location, price) on scheduled basis
DATA-06
Aggregate raw transactions into configurable time buckets (daily/weekly/monthly) per SKU/location
MODEL-01
Train TensorFlow-based forecasting models at defined SKU/location/time-bucket granularity
MODEL-03
Version and store trained models with metadata (training date, hyperparameters, evaluation metrics)
FORECAST-01
Generate demand forecasts for each active SKU/location combination on scheduled basis
FORECAST-03
Store forecast outputs with associated confidence intervals or prediction ranges
API-01
Expose REST API for retrieving forecast data by SKU, category, location, and date range
API-04
Implement authentication (token/session-based) for all non-public endpoints
UI-01
Display demand forecast trends per SKU/category/location with historical actuals overlaid
UI-03
Display forecast accuracy metrics (MAPE) at aggregate and SKU levels
AUTH-01
Support user authentication (login/logout) with secure credential storage
AUTH-02
Support role-based access control: Admin, Planner (view/interact), Viewer (read-only)
